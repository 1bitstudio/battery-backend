# Battery Analysis Backend

Backend-часть системы анализа деградации аккумуляторов.

## О проекте

Данный модуль представляет собой серверную часть веб-приложения по анализу деградации аккумуляторов. Backend является центральным звеном системы и обеспечивает взаимодействие между клиентским web-интерфейсом, базой данных, брокером сообщений Kafka и ML-сервисом прогнозирования.

Основная задача backend-части — принимать пользовательские запросы, обрабатывать и валидировать входные данные аккумуляторов, подготавливать их к анализу, сохранять результаты и передавать их на frontend для отображения в дашборде.

## Основной функционал

Backend-часть реализует следующие возможности:

- регистрация, аутентификация и управление пользователями;
- подтверждение email с помощью шестизначного кода;
- JWT-авторизация и обновление токена доступа;
- прием и валидация CSV-файлов с данными аккумуляторов;
- проверка структуры файла и обязательных полей;
- хранение пользователей, запросов, измерений и результатов прогнозирования;
- преобразование CSV-данных в JSON-структуру для ML-сервиса;
- отправка данных в ML-сервис через Kafka;
- прием и сохранение результатов прогнозирования от ML-сервиса;
- передача результатов клиентской части для визуализации.

## Обработка данных

После загрузки CSV-файла backend выполняет проверку его корректности: расширения, непустого содержимого и наличия обязательных столбцов. Далее данные построчно считываются, преобразуются в серверные объекты и сохраняются в базе данных с привязкой к конкретному пользовательскому запросу.

На следующем этапе данные группируются по циклам работы аккумулятора, сортируются по порядку измерений и преобразуются в JSON-формат, необходимый для передачи в ML-сервис. Такой подход позволяет отделить хранение исходных измерений от логики прогнозирования и обеспечить повторное использование данных в истории запросов.

## Взаимодействие с ML-сервисом

Обмен данными между backend и ML-сервисом реализован через Apache Kafka. Backend отправляет подготовленный JSON в соответствующий Kafka topic, после чего ML-сервис выполняет прогнозирование и возвращает результат обратно через другой Kafka topic. После получения ответа backend сопоставляет его с исходным запросом и сохраняет результат в базе данных.

Такой механизм позволяет организовать асинхронную обработку данных и снизить зависимость серверной части от времени выполнения модели.
